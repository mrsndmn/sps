# SPS MTP Implementation Plan

> **For agentic workers:** Use the approved same-session implementation; independent model and decoding domains use superpowers:dispatching-parallel-agents, with integration and whole-branch adversarial review.

**Goal:** Adapt new prediction embeddings for all requested horizons and measure reference-correct generation speed.

**Architecture:** Keep the pretrained SPS frozen. Implement explicit real-state and grouped-prediction attention, preserving shared softmax normalization and document causality. Expose prefix KV caching for draft and parallel verification; use exact greedy/stochastic acceptance and correction. Reuse project MLSpace staging and receipts with an isolated suite.

**Tech stack:** Existing Python, torch, Triton/flex attention where verified, torchrun DDP, existing shared MLSpace library.

**Spec:** run/deep-interview/deep-interview-sps-mtp.md

## Global Constraints
- N=2,3,4; each job four GPUs; 1B input tokens; 24-hour cap.
- Only N-1 new input embeddings trainable, copied from original predict embedding.
- Group-local predict causality and no future-text/document leakage.
- Original SPS-10B remains the reference; greedy and sampling both required.
- Prepared data, shared environment and code snapshots reused; never edit shared mls.
- Numeric choices live in source. All implementation committed and reviewed.

## Review Focus
- Tied output weights must remain frozen; AdamW cannot modify frozen rows.
- No leakage via real-token states or other groups at any layer.
- Proposal probabilities must match the actual generation algorithm on rejection.
- Cache state after partial rejection must match accepted real tokens exactly.
- Throughput estimate must include the real DDP training computation and token count.

### Task 2: Exact speculative algorithm
Files: src/modeling/mtp_speculative.py; tests/test_mtp_speculative.py.
Consumes: callback propose(prefix)-> probabilities [N,V]; verify(prefix, proposals)-> probabilities [N+1,V].
Produces: speculative_generate callbacks, greedy/sample settings, output token IDs and counters.
A proposal block is drawn from the fixed-prefix per-horizon distributions: later slots do not consume sampled earlier tokens. Verify conditions on all proposed previous real tokens. Include residual rejection correction and bonus token when all proposals accepted. Cache ownership stays in callback adapter.

## Implementation evidence and rulings
- Task 1: model/cache implementation committed dcc721a; tiny CPU and compiled CUDA
  tests cover P1 equivalence, leakage, frozen updates and rollback.
- Task 2: exact generic decoder committed 59017a1; 42 tests passed including CUDA.
- Task 3: registry, target masks, matched samplers and runtime guards implemented;
  combined orchestration/adapter/decoder tests passed (69 tests at integration).
- Ruling: use the original native sequential verifier for exact reference probabilities,
  rather than treating an N=1 SDPA wrapper as identical to native decoding. Real
  checkpoint checks found shape-dependent BF16 probability errors around 0.0003,
  plus different native decode output precision. The proposal may approximate the
  reference, but verification must use the native source path. Cost: first speed
  measurements include sequential verification and do not establish the potential
  of a future parallel-verification kernel; report this limitation explicitly.
- Initial full CPU suite: 86 passed, 66 skipped, one torch.compile test failed due
  toolchain headers. Targeted rerun with the existing shared headers and system
  GCC/G++ passed; no model source change needed for this environment issue.
